# Архитектура

```
rules/                  Правила очистки (TOML), по папке на ОС
crates/trufi-core       Ядро без привязки к ОС
crates/trufi-platform   Реализации для конкретных ОС
apps/desktop            Приложение: Tauri (src-tauri) + интерфейс на Svelte (src)
```

## Слои

**trufi-core** ничего не знает об ОС. Модули:

| Модуль | Что делает |
|---|---|
| `rules` | Читает и проверяет пакеты правил, раскрывает шаблоны путей (`%LOCALAPPDATA%`, `~`, `*`, списки вроде `%DRIVES%`) |
| `scanner` | Обходит пути правил параллельно, считает размер, не трогает файлы; устраняет двойной учёт пересекающихся правил |
| `cleaner` | Удаляет только найденное, перепроверяя каждый путь |
| `safety` | Последняя линия защиты: запрещённые папки и требования к корню очистки |
| `leftovers` | Эвристика остатков удалённых программ (сравнение с установленными, давность, размер, признаки сохранений) |
| `large_files` | Крупные файлы на всех дисках |
| `monitor` | Нагрузка системы через `sysinfo` (CPU, память, диски, сеть, процессы) |
| `updates` | Обновления ОС: версия и срок её поддержки (Windows по календарю Microsoft, macOS — три последние версии), ожидающие обновления, давность последней установки |
| `drivers` | Драйверы и устройства с ошибками; связывает драйверы с обновлениями из Windows Update |
| `health`, `advisor` | Оценка 0–100 и советы. Отдают идентификаторы и числа, текст формирует интерфейс |
| `platform` | Трейт `Platform`: всё, что зависит от ОС |

**trufi-platform** реализует `Platform`:

- `windows`: переменные путей и все фиксированные диски, библиотеки Steam на любых дисках, реестр установленных программ (с учётом игр Steam, перенесённых в другую библиотеку), автозагрузка через `StartupApproved`, корзина через `SHQueryRecycleBin`/`SHEmptyRecycleBin`, проверка и запрос прав администратора, запуск деинсталляторов через `ShellExecute`. Обновления берутся из Windows Update Agent (COM), драйверы и ошибки устройств из WMI (`Win32_PnPSignedDriver`, `Win32_PnPEntity`); оба запроса идут через PowerShell без окна консоли.
- `macos`: программы — пакеты `.app` в `/Applications` и `~/Applications` (имя, версия и bundle id из `Info.plist`, размер по занятым блокам); удаление — в Корзину через Finder или фирменным деинсталлятором из папки программы. Автозагрузка — plist-файлы launchd в `~/Library/LaunchAgents`, `/Library/LaunchAgents`, `/Library/LaunchDaemons`, состояние из `launchctl print-disabled`, переключение через `launchctl enable/disable` (для системных служб — с паролем администратора через `osascript`). Обновления — `sw_vers`, `softwareupdate --list`, `/Library/Receipts/InstallHistory.plist`. Проверка полного доступа к диску; переменная `%CONTAINERS%` (контейнеры других программ) появляется только при нём, чтобы macOS 14+ не спрашивала разрешение при каждом сканировании. Объекты входа — через System Events; выключенные запоминаются в `~/Library/Application Support/app.trufi.cleaner/disabled-login-items.json`, чтобы их можно было вернуть. Давление памяти — `sysctl kern.memorystatus_*`. Особые пункты очистки (`special`): снимки Time Machine (`tmutil`), неработающие симуляторы (`xcrun simctl`), кеш сборки Docker. Разборщики вывода покрыты тестами, которые идут и на Linux. `scripts/mac-diagnostics.sh` собирает отчёт о реальном Mac без изменений на нём.
- `linux`: не цель релиза, нужен, чтобы ядро и интерфейс можно было разрабатывать на любой машине.

**apps/desktop/src-tauri** держит состояние (последний скан, история CPU, монитор) и отдаёт команды интерфейсу. Тяжёлая работа идёт в фоновых потоках, прогресс сканирования приходит событиями `scan-event`.

Настройки окна и сборки для Mac лежат в `tauri.macos.conf.json` (Tauri накладывает его поверх `tauri.conf.json`): родные кнопки окна поверх своей шапки, `.app` и `.dmg`, минимальная версия macOS 11, ad-hoc подпись. `Info.plist` объясняет, зачем приложению управлять Finder, `Entitlements.plist` разрешает это при hardened runtime.

**apps/desktop/src** — интерфейс на Svelte 5 без UI-библиотек. `lib/api.ts` — единственная точка вызова бэкенда; вне Tauri он подменяется `lib/mock.ts`, поэтому интерфейс можно разрабатывать в браузере на любой ОС. `lib/os.ts` сразу знает, на какой ОС запущен интерфейс: от этого зависят шапка окна, страница «Драйверы» и формулировки (`?os=macos` в браузере показывает вид для Mac).

## Как расширять

- **Новое место очистки**: добавить `[[rule]]` в `rules/<ос>/*.toml`. Код менять не нужно. Пользователь может положить свои `.toml` в папку правил (путь показан в настройках).
- **Новая ОС**: реализовать `Platform`, добавить пакет правил и подключить его в `rules/builtin.rs`.
- **Новый тип очистки**, который не сводится к обходу папок: вариант `Special` в правилах и обработка в `scanner`/`cleaner` (так сделана корзина).
- **Новый язык интерфейса**: словарь в `lib/i18n.ts`. Ядро текст не формирует, кроме названий в пакетах правил.
