# Архитектура

```
rules/                  Правила очистки (TOML), по папке на ОС
crates/trufi-core       Ядро без привязки к ОС
crates/trufi-platform   Реализации для конкретных ОС
apps/desktop            Приложение: Tauri (src-tauri) + интерфейс на Svelte (src)
```

## Слои

**trufi-core** ничего не знает об ОС. Модули:

| Модуль | Что делает |
|---|---|
| `rules` | Читает и проверяет пакеты правил, раскрывает шаблоны путей (`%LOCALAPPDATA%`, `~`, `*`, списки вроде `%DRIVES%`) |
| `scanner` | Обходит пути правил параллельно, считает размер, не трогает файлы; устраняет двойной учёт пересекающихся правил |
| `cleaner` | Удаляет только найденное, перепроверяя каждый путь |
| `safety` | Последняя линия защиты: запрещённые папки и требования к корню очистки |
| `leftovers` | Эвристика остатков удалённых программ (сравнение с установленными, давность, размер, признаки сохранений) |
| `large_files` | Крупные файлы на всех дисках |
| `monitor` | Нагрузка системы через `sysinfo` (CPU, память, диски, сеть, процессы) |
| `health`, `advisor` | Оценка 0–100 и советы. Отдают идентификаторы и числа, текст формирует интерфейс |
| `platform` | Трейт `Platform`: всё, что зависит от ОС |

**trufi-platform** реализует `Platform`:

- `windows`: переменные путей и все фиксированные диски, библиотеки Steam на любых дисках, реестр установленных программ (с учётом игр Steam, перенесённых в другую библиотеку), автозагрузка через `StartupApproved`, корзина через `SHQueryRecycleBin`/`SHEmptyRecycleBin`, проверка и запрос прав администратора, запуск деинсталляторов через `ShellExecute`.
- `unix`: macOS и Linux. Пути, защита, корзина и базовый список программ; отправная точка для порта на macOS.

**apps/desktop/src-tauri** держит состояние (последний скан, история CPU, монитор) и отдаёт команды интерфейсу. Тяжёлая работа идёт в фоновых потоках, прогресс сканирования приходит событиями `scan-event`.

**apps/desktop/src** — интерфейс на Svelte 5 без UI-библиотек. `lib/api.ts` — единственная точка вызова бэкенда; вне Tauri он подменяется `lib/mock.ts`, поэтому интерфейс можно разрабатывать в браузере на любой ОС.

## Как расширять

- **Новое место очистки**: добавить `[[rule]]` в `rules/<ос>/*.toml`. Код менять не нужно. Пользователь может положить свои `.toml` в папку правил (путь показан в настройках).
- **Новая ОС**: реализовать `Platform`, добавить пакет правил и подключить его в `rules/builtin.rs`.
- **Новый тип очистки**, который не сводится к обходу папок: вариант `Special` в правилах и обработка в `scanner`/`cleaner` (так сделана корзина).
- **Новый язык интерфейса**: словарь в `lib/i18n.ts`. Ядро текст не формирует, кроме названий в пакетах правил.
